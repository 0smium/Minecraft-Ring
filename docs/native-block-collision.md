# MC 建筑的法环原生碰撞候选

0.3.4，默认关闭，尚未实机验收。将固定 EldenCraft 的真实方块形状/合并与原生 Havok 刚体方法移入本项目，不加载对方模组或DLL。参考提交为 `ba7591cdde9fb16e17552cfe53546f44d0fd856e`，MIT版权/许可随移植代码保留。

## 本批已接通的链路

1. Core集成服务器仅从ER Bridge世界、本机所属玩家周围取方块。读取真实 `VoxelShape`，排除代理地形、空气与纯流体；半砖、楼梯、含水固体保留实际碰撞形状。
2. 相同截面的相邻/重叠盒子按轴合并，不跨越真实缝隙。分区与修改版本缓存；放置、拆除、相邻格改变、动态形状和区块卸载都会使对应结果更新。
3. 原版世界坐标经 `CoordMap` 转成稳定ER坐标，包括region偏移、单位比例和Z翻转后重新排序边界。每份快照带宿主/MC进程与启动时间、Core代数、生命、区域、世界epoch及时间。
4. 原生核对完整EXE SHA、代码/类型、实际离线状态、当前物理世界和执行线程，用现存可站立静态地面的材质/碰撞过滤模板，调用原生shape/body构造、加入、销毁及引用释放。
5. 拆除和离开窗口按差集回收自己的对象；身份不符时不删除替代对象。世界已换则隔离旧对象记录；不解引用未知旧世界。

每个世界窗口最多48×32×48格、每次最多32768格扫描预算、选取最近512个合并盒。源扫描未完成/邻区不可读时发布空的“不完整”状态，不沿用旧障碍；完整扫描超过512盒则明确标记近邻截取。原生每次最多创建96、移除128，创建另限时约2ms。实际帧时与密集Scaffold场景仍需测。

原生从当前角色认可的静态地面取得过滤模板，五米内找不到合适地面时显示等待原因，不猜一个碰撞层。刚体进入宽相位只说明注册完成，不代表敌人、箭、法术或近战的碰撞都正确。

## 避免建筑被重复读成法环地形

原生射线与本组件自有盒相交时返回 **unknown**，不把它当作原生墙或空地。粗采样保留对应列；精细采样与通行清理放弃未知批次。平台/赐福交互探测同样不能用unknown证明地面存在或通道为空。

这是保守的几何遮挡判定，可能暂缓墙附近的地形更新；拆除完成后恢复正常采样。现有MC方块本身仍提供MC碰撞，不需要再生成一层假terrain来托住玩家。

## 开关与配套

以后集中验证时使用：

```powershell
# 只构建与预检，不启动或修改游戏配置
.\Launch.ps1 -B01 -NativeBlockCollision -CheckOnly
# 已关闭游戏、更新本批两个DLL后，才用于人工验证
.\start.bat -B01 -NativeBlockCollision
```

不开开关就是既有行为。实验同时要求MC启动属性与ER启动环境标记；不能对已经运行的ER临时启用。启用期间拒绝Core热重载，更新DLL要完整退出ER。正常只重启MC可以让陈旧快照先被回收，但重新启动整套实验仍走上述完整流程。

只读诊断：`python tools/inspect_native_blocks.py`，可加 `--output runtime/experiments/<name>.json`。MC日志记录 `Native blocks:`，原生日志记录 `native blocks:`；包含快照数、实际owned数、待处理数、隔离数和失败原因。

快照超过750ms、MC退出/暂停、F8交回ER、死亡/加载时停止创建并进入预算清理。**本切片不承诺F8后建筑仍挡住原生角色**，不让暂停的MC用旧窗口永久控制物理世界。原生离线/世界身份无法验证时则保留归属记录并暂停删除；这是待排查状态，不算清理成功。隔离对象不保存到游戏存档。

## 物理执行阶段依据

参考EldenCraft使用`ChrIns_PostPhysics`（113），本项目现有Core是`WorldChrMan_PostPhysics`（117），不能仅凭名称假定相同。对目标EXE磁盘核对后，实际固定排程表中Havok post（99）和117都在lane 0，99行先执行；113位于两者之间。Havok post等待线程池任务、回收任务图并清空`HavokMan+0xA8`后才继续。

因此保留本项目117回调，在本帧生命/坐标系更新后、地形射线之前处理碰撞。除执行线程检查外，原生驱动还要求`+0xA8`可读且为0，否则创建和删除都暂停。相关回调指令、清理指令和调度行纳入启动签名校验；本机简要取证位于忽略目录`runtime/experiments/collider-research/post-physics-evidence.json`。这些是静态调度证据与运行时拒绝条件，实机仍须验证。

## 后续一次集中验证

先在无敌人、安全平地放一堵普通实心墙与一块地板，对照诊断的desired/owned/complete；走近后再分别检查普通敌人身体、箭/法术、近战。拆除应恢复通行，半砖/楼梯按真实形状表现。F8/暂停、死亡/传送、MC退出需观察停止创建及回收/隔离日志。

各碰撞层分开记录；敌人被挡住但不会绕行不能写成碰撞失败，也不能写成导航已适配。原生导航网格没有随建筑更新。

本批没有实现表面采集或挖穿法环山体。下一步资源玩法须先确认有效原生材质，再接MC工具、硬度、战利品与耗竭；具体边界见[EldenCraft研究](eldencraft-physics-research.md)。
