# 原生菜单自动交接候选

0.3.3实现，尚未实机验收。目标是在MC中按现有交互键 **R** 使用赐福等原生对象时，将控制交给法环菜单，正常离开后回到MC；保留用户主动F8的控制权。

## 当前行为

1. 按R前取得同一角色、生命和区域的只读状态；发送现有原生action请求，不重复发送。
2. 收到对应成功确认，并在请求后8秒内观察到真实原生blocking menu，才使用既有overlay交接到ER。
3. 菜单关闭、原生action-ready、休息相关标志全部清除且宿主可用，持续350ms并读到新帧后返回MC。停留菜单期间没有强制超时。
4. 手动F8、切到其他应用、身份/生命/区域改变、数据过期或宿主不可用时取消自动返回。取消后可按F8自行接管。

不能把所有输入禁用都当成菜单，也不会因为普通MC屏幕或用户手动切到ER就自动抢回。只有MC发起的这一轮有效交互拥有返回资格。

## 数据与已知限制

Core通过64字节HINT v1读取菜单、休息阶段、action-ready，带PID、启动时间、generation、hostLife、区域和帧/时间；Java要求500ms内数据、帧差不超过120。原生初始化验证当前2.7.1.0代码签名和运行时对象类型，读两次拒绝变化中的链路。

原生状态来自CSMenuMan的blocking job与announce view active、LuaEventMan休息位5–8以及CSActionButtonMan动作标志；不是只看画面上的提示文字。退出到标题位亦参与禁止返回。菜单读写都仍归ER执行，本批只观察这些状态。

**真实赐福退出后rest flags的清除时间尚未观察。** 若它们延迟或未清零，候选会留在ER控制，不能声称保证自动返回；下一轮只需记录一次退出过程。对话、商店、箱子等也不能由赐福测试代替全部验收。

工具与证据见[本批记录](experiments/2026-10-14-post-validation-fixes.md)。日志会记录 `Interaction: native menu opened` 和 `Interaction: native menu closed`；没有第二条时先保留原生控制并用F8退出候选流程，不反复发送交互。
