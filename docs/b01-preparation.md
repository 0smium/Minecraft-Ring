## 角色与点数规则

- 持久键是 `playerId + campaignId + characterId`。这些 UUID 由可信服务端的角色绑定流程保存、分配，不能每次启动重新生成，不能采用原生指针或进程 ID。
- 每次宿主重连分配新的 `sessionId`；序号只在该会话中递增。同一会话重复注册不清空序号检查。旧连接延迟到达的断开事件不会移除新连接。
- `observe(authenticatedPlayer, snapshot)` 的第一个参数必须来自已经认证的连接。仅有 UUID 模型不构成身份认证，也不能证明远端声称的法环等级真实。
- `READY` 要求有效正等级；`LOADING` / `UNAVAILABLE` 不创建基线或发点。未连接用空快照表示。原生适配器还必须判定角色有效性、存档切换与心跳过期；本层没有时钟超时机制。
- 首次有效等级成为基线，默认由调用方传入每级点数与初始点数。既有高等级角色不会自动补发全部历史点数。
- 累计额度为 `初始点数 + (最高已确认等级 - 首次等级) × 每级点数`。回档后恢复到已见等级不会再发一次；更换角色/战役必须显式切换绑定。
- `erbridge:er_level` 是累计点数来源，交给技能框架覆盖该来源的总额度，不能每次把返回值累加。技能购买、已花点数与退款由技能框架管理，本内核不维护第二份消费账本。
- 先成功保存等级额度，再确认序号并向调用方返回额度；I/O 错误可用同一快照重试。技能框架写入属于下一步事务：适配器应保留待应用额度、失败重试，并在登录时重新对账。不能把第二次读取同一序号一定有返回值当成重试方案。
- 已存档角色保留其原有计分曲线。更改构造默认值只影响新角色；旧曲线的迁移需要显式设计。

`FileLevelProgressStore` 将记录保存到调用方指定目录下的
`<campaign>/<player>/<character>.properties`。实际接入应选择服务端所属世界的数据目录。
记录有版本与绑定检查，损坏/未知版本直接报错，不当成新角色重置。
单条记录通过同目录临时文件、文件刷盘和原子替换保存；文件系统不支持原子替换时操作失败。
这是单服务端线程、单写入者存储，不是多进程数据库，也没有承诺断电后目录元数据持久性；Windows 文件替换需实机确认。

## 能力与配置规则

`AbilityPolicy` 接收每项技能的等级表，读取技能框架给出的已学等级，生成该角色的 `CapabilitySnapshot`。
缺失技能等级按未解锁处理。未解锁可以隐藏或显示为灰色，但两个显示方式都会拒绝激活请求。

调用方必须在合并完整配置后，使用**当前服务端能力视图**调用 `authorize`，并实际使用其返回的规范化数值。未知模式、未知/缺失参数、NaN/无穷大均被拒绝；有限数值按当前技能等级的上下限收敛。配置校验必须发生在启用副作用之前，并且运行中的执行路径也要受当前策略约束。

更换策略使用新的递增版本号；旧版本请求被拒绝，原有数值按新上限重新计算。退款/锁回技能也要重新生成视图。这里实现了不可变策略计算与校验，**没有实现配置文件热重载、ClickGUI/TabGUI 刷新、真实模块停用清理或服务端移动/攻击校验**。客户端自己修改代码时，单靠本地策略不构成反作弊。

若新等级表删去了玩家已学等级，计算会拒绝该状态，不能静默提升或降级。重载接线时需先构造新策略、验证所有在线角色及待迁移数据，再在服务端线程切换；任何失败保留旧策略。适配器停用被撤销的模块时必须执行其清理逻辑。

验收里的 `ground` / `single_target` 是 Bridge 语义标识，`multiplier` / `range` 是示例参数。它们不是已经验证的 LB/Meteor 模式名称。示例 Speed 上限 1.1/1.2、Aura 范围 2.5/3.0 只存在于测试夹具中，不代表最终平衡，也不代表已经改变实际移速或攻击距离。

## 一次运行的验收

在仓库根目录执行：

```sh
python tools/test_b01_preparation.py
```

需要包含 `jdk.compiler` 的完整 JDK 17 或更高版本。可用
`--java-home <JDK目录>` 或 `JAVA_HOME` 指定，也支持仓库 `.tools/java/*/bin/` 及 PATH。
不需要下载依赖。脚本直接编译 10 个真实生产源码文件和 2 个测试文件，启用全部 javac 警告并将警告当错误；临时输出在退出时清理。
独立验收的 `--release 17` 只用于这组无游戏依赖的代码，未改变 Fabric 工程的 Java 21 编译目标和现有工具链。

2026-10-13，在 Linux / OpenJDK 17.0.20 环境验证通过：

| 验收组 | 结果 |
| --- | --- |
| 未就绪状态、首次等级、重复和乱序、等级回退、重连和延迟断开 | 通过 |
| A/B 玩家、角色、战役隔离；拒绝存储返回错误角色记录 | 通过 |
| 写入/读取失败重试、曲线持久化、坏档/未知版本/错误绑定/超大记录、点数溢出 | 通过 |
| 锁定与显示策略、参数收敛、非法配置、策略切换、退款后锁定、不可变视图 | 通过 |
| 模拟双玩家：A 从 10 升到 12 得 2 点，B 从 20 升到 21 得 1 点 | 通过；技能等级由测试夹具指定，未运行购买流程 |
| 再启动独立 JVM，读取同一存储并恢复 A=2、B=1 | 通过 |

脚本共运行 16 组模拟场景及 1 组独立 JVM 恢复场景。它没有启动 MC/ER，没有运行完整 Gradle 构建，也不证明现有战斗/生命广播已做到多人隔离。原生等级字段、技能树 UI、LB/Meteor 共载、真正热重载和真实双游戏联机仍未验收。
