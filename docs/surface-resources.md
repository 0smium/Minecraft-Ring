# 地表基础资源第一版

2026-10-14 首版地表生成，2026-10-15 补人工标记的区域排除，优先于地下挖矿实施。已有 ER Bridge 世界也能使用，不需要重建存档。**代码和离线检查已完成，尚未启动游戏验证生成位置、合成画面和实际采集。**

## 内容与玩法

| 资源 | 实现 | 用途 |
| --- | --- | --- |
| 橡树、少量桦树 | 4–5格树干、普通树叶，小树模板 | 原木、木板、工作台、木工具；树叶沿原版规则掉树苗/苹果/木棍 |
| 蒲公英、虞美人 | 稀疏小花丛 | 采集、染料 |
| 矮草 | 小片普通矮草 | 原版概率掉小麦种子 |
| 甜浆果 | 少量成熟浆果丛 | 食物、采收后原版再生长 |
| 露天石堆 | 小块普通石头，部分石堆含1块煤矿 | 木镐采圆石、石工具、熔炉；煤/木炭供火把与燃料 |

使用MC原版方块、物品、掉落表、合成和随机刻，不添加替代采集货币或无限领料命令。树叶保留衰败，按树干连通距离初始化，不使用永久树叶。植物有少量可见的原版土/草基座；砍树后可在土上种回树苗。树苗正常长大与骨粉使用原版逻辑，长大后的树冠目前不再向原生法环申请净空，因此紧邻原生建筑种树仍需实机观察。

这里新增的是MC资源，不把法环现有大树、草花直接变成可砍对象。地下石层、洞穴、铁/金/钻石矿脉和完整农田/生物分布尚未实现。

## 自动生成与保存

仅 ER Bridge 主世界、本机法环宿主处于有效MC接管状态时运行，默认开启。确定性16×16格候选每格有65%概率的小树、两处草花候选、少量浆果或石堆；实际还要通过地表筛选。位置取决于世界种子、法环区域、稳定坐标锚点，和探索顺序无关。

检查玩家21格范围内的候选，至少离玩家6格，树冠也落在24格普通地形采样范围内。中心需两次稳定原生采样，整个占地必须已观测、接近平坦、上方采样没有碰撞、没有已知移动支撑。树干/树冠完整包围盒要为空气，不能替换玩家方块、现有植物或液体；不会请求加载新区块，也不会在玩家/敌人身上放树。每秒至多请求一个候选的缺失地表补采，复用原调度器、2048射线批次和原生2毫秒帧预算；不删除旧碰撞或反复清空稳定证据。初到区域不会立刻铺满远景，走动或短暂停留后逐渐具备生成证据。

每半秒至多落下一处完整资源，候选查找有数量/时间预算；一株小树的写入作为一个有界操作完成。生成失败会回滚方块及原精细碰撞NBT，并停用自动生成供检查。精细碰撞缓存重放已加普通MC方块保护，不能把生成树干/花草写回隐形地形。

普通方块存入正常MC区块；完成标记保存在世界的 `data/erbridge_surface_resources.dat`。砍完、重采样、切区、死亡或正常保存重进都不会重新生成同一候选。浆果再生长、自己种的树苗长成属于原版生长，不是生成器补货。关闭后也保留已生成内容；没有清空标记或强制补货命令。

管理员命令（仅本机宿主）：

```text
/erbridge resources status
/erbridge resources off
/erbridge resources on
/erbridge resources exclude here 24 赐福门口
/erbridge resources exclude zone 当前室内地图
/erbridge resources exclude list
/erbridge resources exclude list 2
/erbridge resources exclude remove 1
```

`status` 报告开关、已完成候选数、有效采样数、当前映射/全部禁区数与最近状态。记录类型缺失/格式不兼容时停止新增，不按空账重新刷。

## 标记不合适的生成区域

在不希望继续长资源的位置输入 `exclude here <半径> [名称]`：以当前 MC 所在方块中心为圆心，禁止半径内**全部高度**的新资源。半径为 1–256 格，名称可省略，最多 48 字；不是只排除脚下一个高度层，楼上楼下都会受到限制。树干在圆外、树冠足迹进入圆内时也拒绝整株生成。规则先于地表补采队列筛选，所以不会持续为已排除候选请求原生射线。添加规则会撤回已有资源补采请求，随后只排队未排除位置。

`exclude zone [名称]` 禁止当前法环区域及稳定坐标映射内的全部后续新增。**zone 是桥接所识别的区域，可能覆盖大片开放世界，不等于眼前一个小房间**；局部门口、水边优先用 `here`。不预设任何地图编号，也不会宣称能自动判断屋顶、水面或室内。

`exclude list [页码]` 每页显示 8 条规则、编号、名称、zone/region、范围及是否属于当前映射；最多保存 128 条。`exclude remove <编号>` 撤销指定规则，重叠的其他规则仍有效。规则绑定世界存档及法环 zone、region、三轴锚点、比例和朝向，切换到其他映射不会把相同 MC 坐标误认为原禁区；重启宿主不会因进程/生命编号变化丢失规则。新增时必须已连接法环、处于 MC 控制且区域同步稳定；已断开时仍可查看、移除已保存规则。

所有命令需要本机宿主及管理员权限，LAN 玩家和控制台不能代替宿主创建禁区。规则只影响**后续新增**：不会删树、清方块、撤销旧资源，也不会清空采集收据。撤销禁区后，未曾生成过的候选可重新参与筛选，采过的位置仍不会补刷；种子和候选布局不变。新格式为 `erbridge_surface_resources.dat` v2，原 v1 的开关和收据无损读取；任何损坏的 v2 规则都会锁住生成/写回，保留原账供排查。

离线检查覆盖真实二进制 NBT 的 v1→v2 迁移、关闭状态和采集收据保留、切区/锚点隔离、负坐标/圆形与整棵树足迹相交、重叠规则撤销、规则上限和坏格式拒绝。游戏内命令反馈、实际区域覆盖与重进保存仍留给集中验证。

## 首版限制与集中验证

现有射线能判断开阔、坡度和碰撞，尚不能准确区分草地、石路、露天屋顶或静止平台；40米上方射线也不是整张地图的天空证明。先在普通野外地面检查分布；不宣称全地图生态/室外识别完成。水面若未进入原生碰撞射线，也不能仅凭虚空世界的MC空气排除，水边是明确待验项。观察到不合适的位置时可标记局部禁区、排除当前区域，或关闭新增；材质自动筛选与原版生物群系/树木生成器尚未接入。

开启可选 `-NativeBlockCollision` 时，原木/树叶和其他普通MC方块一起参与现有512盒上限；默认关闭时没有这部分原生开销。不要将该实验的开关与资源是否能采集混为一谈。

下一轮由用户集中验证：普通野外走动→看到树花与石堆→砍树做工作台/木镐→采石做石工具/熔炉→采花、草与浆果→等树叶衰败/种回树苗→正常保存退出MC再进，确认采过的原始资源不补回。顺便观察门口、坡地、水边和原生场景遮挡；没有观察到的项目继续记待验。

相关代码位于 Core 的 `dev.ermc.bridge.world`，不依赖 Character、Skills、LB 或 Meteor。复用地表采样与有限补采，不增加射线协议、单批/单帧预算或DLL偏移；自定义调试过滤器启用时停止资源生成。
