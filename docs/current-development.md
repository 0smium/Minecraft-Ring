## 下一批成组交付

1. **独立角色模组与统一策略一起迁移。** 保留可用底座和既有功能，把 B01/B02 的角色 UI、用例和规则移到角色模组；适配器隔离可选依赖。提供独立构建/加载证据，不能只加空 JAR。
2. **复用式装备样例。** 原版 menu/screen/slot 附加页，选择一件真实已持有装备，完成装配→原生确认→刷新→卸下。保留 MC 正常库存；不用第二份可消费库存代替 ER 数据。
3. **统一能力配置与状态。** 在既有策略/Value 接线泛化 Speed/Aura；保留用户合法调参，升级扩范围；睡眠、退款、失联通过统一策略收回冲突能力。更多技能主要增加映射描述，有确切 API/事件差异才增加局部适配。
4. **骑乘准入与启动一致性。** 先验证法环允许/禁止/未知骑乘条件；原版 Horse 继续负责运动。让各 profile 在启动 ER 前检查其真实依赖，不顺便改写马物理。
5. **同批配套实测。** 固定 DLL、Core/角色/适配器 JAR、技能数据与 profile；测试下表，逐项标通过、失败、未测。然后按已验证装备/动作接口扩展施法样例。

## 集中验证

| 场景 | 通过依据 |
| --- | --- |
| Core-only / Core+角色 / 角色+Skills+LB / 独立 Meteor | 按组合加载，缺少可选组件时无类加载崩溃，Core 不要求 Skills 构建制品 |
| 升级与授权 | 升一级只发一次；升级不强行抬高用户当前值；超范围 GUI/config 导入被统一约束；退款、重连正确 |
| 状态组合 | Core 无能力端基线与 LB/Meteor 开启模块对照；冻伤减速符合选定规则；睡眠不能主动行动且仍受伤/击退 |
| 装备页 | 与法环数据一致；真实装配/卸下成功后更新；失败不伪装成功，正常流程不按 F8 |
| 坐骑 | 原生允许区、禁止区、未知区；召唤与跨边界行为正确；允许区内再测正常净空与 MC 建筑组合 |
| 回收与身份 | 下马、F8、死亡、重连、满包、马菜单；不吞/复制装备、不影响普通马或 LAN 来宾 |
| Meteor | 真实启动与代理目标/HP/攻击可用；尚未实现成长时明确保持实验配置，不冒充受技能授权 |
