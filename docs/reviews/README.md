# Review 与问题记录

用户于 2026-10-12 要求后续 review 建议直接留在仓库。本目录保存跨组件、架构与玩法准备度 review；具体代码问题有对应 PR 时优先留在该 PR 的 review/thread，文档引用它，避免重复维护两份结论。聊天用于说明重点和提供链接。

## 记录约定

- 固定评审提交、范围与日期，区分源码确认、运行记录、推测和未验证项。
- 每条问题写清场景、证据、影响、建议处理的工作线和触发修复的条件。
- 分类使用：当前阻塞、相关功能上线前必须处理、可后置建议；不要把未来多人需求都标成今天的缺陷。
- 状态使用：待处理、已知限制、待实测、已修复并验证、不适用。修复后记录提交和验证证据，不静默删除旧结论。
- 当前无实机测试时明确写出，不把构建、静态阅读或模拟后端结果写成实机通过。
- 运行细节归 `docs/experiments/`；review 保留能够帮助判断的摘要和链接，不提交原始存档、游戏资源或大体积日志。
- 一项问题超过已有时间盒时先记录，按用户当前目标选择下一项可验证能力，避免围绕非阻塞问题无限试改。
- 自 2026-10-13 起按功能组开发、一次配套部署验收多个内容；测试逐项记结果，非阻塞失败不拖住无依赖项。多功能集成不取消对实际制品和实测/模拟后端的区分。
